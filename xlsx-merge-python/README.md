# xlsx-merge (Python)

Python wrapper for the .NET **[XlsxMerge](../xlsx-merge-dotnet)** mail-merge library,
built on [pythonnet](https://github.com/pythonnet/pythonnet). It is domain-agnostic:
it substitutes `#FIELD#` merge fields and expands a repeatable block, exactly like the
.NET library.

```python
from xlsx_merge import render, render_data, parse_csv, parse_file

# CSV data file (or csv_text= for in-memory content), output as bytes:
xlsx_bytes = render("template.xlsx", "data.csv")          # output=None ⇒ bytes
xlsx_bytes = render(template_bytes, csv_text=csv_content)

# Or with in-memory data (Python dicts):
xlsx_bytes = render_data(
    "template.xlsx",
    globals={"COURSE": "Advanced Excel", "DATE": "2024-06-01"},
    rows=[{"EMPLOYEE_ID": 42, "NAME": "Alice", "SCORE": 17.5}],
)

# Generic CSV parser (pure Python, no .NET needed) → (globals, rows):
globals_, rows = parse_file("data.csv")   # or parse_csv(text)
```

Pass an `output=` path to write the file to disk instead of getting `bytes`.

## Requirements

- **Python ≥ 3.9** and `pip install pythonnet`
- the **.NET runtime 8** (not just the SDK): e.g. `apt install dotnet-runtime-8.0`
- a built **`XlsxMerge.dll`** (see below)

## Building the .NET DLL

```bash
cd ../xlsx-merge-dotnet
dotnet build -c Release
# → src/XlsxMerge/bin/Release/net8.0/XlsxMerge.dll (+ ClosedXML.dll and dependencies)
```

The build copies the dependencies (`CopyLocalLockFileAssemblies`), so the whole
`net8.0` directory is self-contained.

## Loading an already-built DLL

The wrapper looks for `XlsxMerge.dll` in this order:

1. **`XLSX_MERGE_DLL` environment variable** — the directory that contains the DLL.
   This is the way to point at a DLL built anywhere (another checkout, a CI artifact,
   a published output…):

   ```bash
   export XLSX_MERGE_DLL=/path/to/XlsxMerge/bin/Release/net8.0
   python examples/render_attendance.py
   ```

   A relative path is accepted (resolved against the current directory).

2. the package directory itself (ship the `net8.0` output next to `xlsx_merge/` if you
   bundle the DLL with the package);

3. default layouts relative to this package:
   - monorepo: `../xlsx-merge-dotnet/src/XlsxMerge/bin/{Release,Debug}/net8.0`
   - standalone: `../src/XlsxMerge/bin/{Release,Debug}/net8.0`

A clear `MergeError` lists every searched path when the DLL is missing. Dependencies
(`ClosedXML.dll`, `DocumentFormat.OpenXml.dll`) are resolved from the same directory
through a CLR assembly resolver registered by the wrapper.

## API

| Function | Description |
|---|---|
| `render(template, data=None, output=None, *, csv_text=None, culture="en-US", marker=None, block="auto", numbers="strict", delimiter=";")` | Mail-merges a template with a CSV data set. Returns the output path, or `bytes` when `output is None`. `template` may be a path or `bytes`. |
| `render_data(template, output=None, *, globals=None, rows=(), fields=None, culture=..., ...)` | Same, with in-memory data (Python dicts). |
| `parse_csv(text, delimiter=";")` / `parse_file(path)` | Pure-Python reader of the `[globals]` / `[rows]` format → `(globals, rows)`. |
| `load_dotnet()` | Loads the runtime and assemblies explicitly (called automatically). |
| `MergeError` | All wrapper errors (data, template, environment). |
| `CsvParseError` | Data format errors, with line numbers (`ValueError` subclass). |

Data format, template conventions and options are documented in the
[.NET README](../xlsx-merge-dotnet/README.md).

## Development

```bash
python -m venv .venv && source .venv/bin/activate
pip install pythonnet pytest
dotnet build -c Release ../xlsx-merge-dotnet   # DLL required by the render tests
python -m pytest tests -v
```

Parser tests are pure Python; render tests skip automatically when the DLL or the
.NET runtime is unavailable. The test template is generated by
`../xlsx-merge-dotnet/samples/make-template` (already committed under `tests/fixtures/`).

```bash
python examples/render_attendance.py
```
